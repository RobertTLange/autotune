# autotune — Design Specification

Automatic hyperparameter optimization CLI. Takes any executable script with a clearly defined metric, uses a coding agent (via headless-cli) to analyze the script and generate an Optuna-optimizable wrapper, then runs a search with configurable trials. Language-agnostic — supports Python, shell, Julia, R, compiled binaries, or anything that prints to stdout.

## Architecture

**Hybrid TypeScript + Python.**

- **TypeScript CLI** — Orchestration layer. Parses arguments, invokes headless-cli for LLM phases, manages the `.autotune/` work directory, runs the Python trial executor, and renders results.
- **Python runner** — Optuna study executor generated by the LLM in Phase 2. The objective function invokes the user's script as a subprocess, passing hyperparameters via CLI arguments and capturing `autotune_metric=` from stdout. Always runs in Python (Optuna requirement), but the user's script can be any language.
- **headless-cli** — Sibling project (`@roberttlange/headless`). Invoked as a subprocess for LLM-powered code analysis and generation.

## Metric Convention

Users mark the optimization target by printing a sentinel line to stdout:

```
autotune_metric=<value>
```

Language examples:

```python
# Python
print(f"autotune_metric={accuracy}")
```

```bash
# Bash
echo "autotune_metric=${accuracy}"
```

```julia
# Julia
println("autotune_metric=$(accuracy)")
```

```r
# R
cat(sprintf("autotune_metric=%f\n", accuracy))
```

- No imports, decorators, or special functions required — just a print to stdout.
- The Python runner captures stdout per trial and parses the last `autotune_metric=` line.
- Supports float values. Multiple prints per run → last value wins.
- If no `autotune_metric=` line is found, the trial is marked as failed.

## Script Invocation

autotune auto-detects how to run the script based on file extension and shebang:

| Extension | Command |
|-----------|---------|
| `.py` | `python3 <script>` |
| `.sh` | `bash <script>` |
| `.jl` | `julia <script>` |
| `.R`, `.r` | `Rscript <script>` |
| `.rb` | `ruby <script>` |
| no extension / executable | `./<script>` (direct execution) |

Override with `--command`:

```bash
autotune run train.jl --trials 50 --command 'julia +nightly'
# invokes: julia +nightly train.jl --lr 0.01 --batch-size 32
```

## Hyperparameter Passing

Hyperparameters are passed to the user's script as **CLI arguments**. The LLM (Phase 1) identifies how the script accepts parameters — existing argparse/flags, positional args, or proposes adding argument parsing if none exists.

The generated Optuna wrapper invokes the script as a subprocess per trial:

```python
def objective(trial):
    lr = trial.suggest_float('lr', 1e-5, 1e-1, log=True)
    batch_size = trial.suggest_int('batch_size', 8, 128)

    result = subprocess.run(
        [command, script, '--lr', str(lr), '--batch-size', str(batch_size)],
        capture_output=True, text=True, timeout=trial_timeout
    )

    for line in reversed(result.stdout.splitlines()):
        if line.startswith('autotune_metric='):
            return float(line.split('=', 1)[1])
    raise optuna.TrialPruned()
```

This means:
- The user's script is never modified in-place — it's invoked as-is
- If the script lacks CLI arg handling, Phase 2 generates a thin wrapper that adds it, or the LLM modifies a copy in `.autotune/`
- The original script is always preserved

## Two-Phase LLM Pipeline

### Phase 1 — Analyze

headless-cli reads the user's script and produces a search space proposal:

- Identifies tunable hyperparameters (learning rate, batch size, architecture choices, etc.)
- Proposes Optuna parameter types and ranges for each
- Identifies how the script accepts parameters (existing CLI args, or proposes adding them)
- Infers optimization direction from metric context
- Returns structured JSON

**Prompt template** (passed to headless via `--prompt-file`):

```
Analyze the following script for hyperparameter tuning.

The script language is: {language}
The script is invoked via: {command} {script}

Identify all tunable hyperparameters and propose Optuna search spaces.
The optimization metric is reported via printing "autotune_metric=<value>" to stdout.

For each parameter, output JSON with:
- name: variable name / parameter name in the script
- cli_flag: the CLI argument name to pass this parameter (e.g. "--lr", "--batch-size")
- type: "float" | "int" | "categorical"
- low/high: for float/int
- log: boolean (for float, whether to use log scale)
- choices: for categorical
- current_value: the hardcoded value in the script

Also identify:
- has_arg_parsing: whether the script already has CLI argument parsing
- needs_wrapper: whether a wrapper script is needed to add arg parsing
- direction: "maximize" | "minimize"
- reasoning: why this direction

Output valid JSON only.
```

The LLM is invoked via:
```bash
headless claude --prompt-file .autotune/analyze_prompt.md --work-dir <script_dir> --json
```

Default agent: **Claude**. Configurable via `--agent <name>`.

### User Confirmation

After Phase 1, autotune displays the proposed search space interactively:

```
✔ Analysis complete. Proposed search space:

  Parameter       Type    Range              CLI Flag        Current
  ──────────────────────────────────────────────────────────────────
  lr              float   [1e-5, 1e-1] log   --lr            0.01
  batch_size      int     [8, 128]           --batch-size    32
  optimizer       cat     [adam, sgd, rmsp]   --optimizer     adam

  Direction: maximize (metric appears to be accuracy)
  Arg parsing: ✔ script uses argparse
  Invocation: python3 train.py --lr <val> --batch-size <val> --optimizer <val>

Confirm search space? [Y/edit/n]
```

- `Y` — Proceed to Phase 2
- `edit` — Opens the search space config in `$EDITOR` as YAML
- `n` — Abort

The confirmed search space is saved to `.autotune/search_space.yaml`.

### Phase 2 — Generate Wrapper

headless-cli generates the Optuna wrapper script using the confirmed search space:

- Reads the original script + search space config
- Produces a self-contained Python script that:
  - Imports optuna and subprocess
  - Defines an `objective(trial)` function
  - Maps `trial.suggest_*` calls to the confirmed parameters
  - Invokes the user's script as a subprocess with sampled params as CLI args
  - Captures `autotune_metric=` from stdout
  - Returns the metric value
  - Creates and runs the study with the specified configuration
- If the user's script lacks CLI argument parsing:
  - Generates a modified copy of the script in `.autotune/` with arg parsing added
  - The Optuna wrapper invokes this modified copy, not the original
  - The original script is never touched

The generated wrapper is saved to `.autotune/<script_name>_optuna.py` and shown to the user for approval before execution.

## CLI Interface

### Commands

```
autotune run <script> [flags]      # Full pipeline: analyze → confirm → run trials
autotune analyze <script> [flags]  # Phase 1 only: propose search space
autotune results [dir]             # View past study results
autotune resume [flags]            # Resume a study from SQLite storage
```

### Flags — `autotune run`

| Flag | Default | Description |
|------|---------|-------------|
| `--trials N` | *required* | Number of Optuna trials |
| `--direction` | `maximize` | `maximize` or `minimize` |
| `--sampler` | `tpe` | `tpe`, `random`, `cmaes`, `grid` |
| `--pruner` | `none` | `none`, `median`, `hyperband` |
| `--storage` | *(in-memory)* | SQLite path for persistence/resume (e.g. `sqlite:///study.db`) |
| `--n-jobs` | `1` | Number of parallel trial processes |
| `--agent` | `claude` | headless-cli agent for LLM phases |
| `--command` | *(auto-detect)* | Override script invocation command (e.g. `julia +nightly`) |
| `--json` | `false` | Output results as JSON to stdout |
| `--output` | *(none)* | Write results to file (JSON) |
| `--work-dir` | `.autotune/` | Directory for generated artifacts |
| `--yes` | `false` | Skip confirmation prompts (accept LLM proposals) |
| `--config` | *(none)* | Path to a pre-defined search space YAML (skip Phase 1) |

### Flags — `autotune analyze`

| Flag | Default | Description |
|------|---------|-------------|
| `--agent` | `claude` | headless-cli agent |
| `--json` | `false` | Output search space as JSON |
| `--output` | *(none)* | Write search space to file |
| `--work-dir` | `.autotune/` | Directory for artifacts |

### Flags — `autotune results`

| Flag | Default | Description |
|------|---------|-------------|
| `--json` | `false` | Output as JSON |
| `--top` | `10` | Number of top trials to show |
| `--storage` | *(none)* | Read from SQLite storage |

### Flags — `autotune resume`

| Flag | Default | Description |
|------|---------|-------------|
| `--storage` | *required* | SQLite storage path |
| `--trials N` | *required* | Additional trials to run |
| `--n-jobs` | `1` | Parallel trial processes |

## Distribution

- **npm package**: `@roberttlange/autotune`
- **Binary**: `autotune` (via package.json `bin` field)
- **Usage**: `npx -y @roberttlange/autotune run train.py --trials 50`
- **Prerequisites**: `python3` + `optuna` (always, for the Optuna runner), `node 22+`, plus the script's own runtime (e.g. `julia`, `Rscript`)
- autotune checks prerequisites on startup and prints install instructions if missing

## Prerequisites Check

On startup, autotune verifies:

1. `python3` is available and version ≥ 3.9 (required for Optuna runner)
2. `optuna` is importable (`python3 -c "import optuna"`)
3. `headless` is available (falls back to `npx -y @roberttlange/headless`)
4. The specified agent is installed (via `headless --check`)
5. The script's runtime is available (e.g. `julia`, `Rscript`) — auto-detected or from `--command`

## Error Handling

- **No `autotune_metric=` in trial output**: Trial marked as failed (pruned), study continues
- **Script crashes during trial**: Trial marked as failed, error logged, study continues
- **Phase 1 LLM failure**: Retry once, then abort with error message
- **Phase 2 LLM failure**: Retry once, then abort with error message
- **All trials failed**: Report error summary, suggest checking the script independently
- **KeyboardInterrupt during trials**: Save partial results, report best so far
